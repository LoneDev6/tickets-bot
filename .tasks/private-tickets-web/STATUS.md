## Current decisions and behavior

- HumbleServers Node/Pterodactyl, fixed port 7777, literal `*.js` launcher for the provider egg. Prebuilt `web/dist` is versioned; no frontend dependency installation or TypeScript/Vite build on the 256 MB server. Preserve `.runtime/` keys and configuration across pulls.
- Official shadcn/ui radix-nova neutral, system light/dark preference. English dashboard and public policy. React handles internal links, URL history and Retry without reloading the document; OAuth and external Discord links retain native navigation. The authenticated session and SSE connection survive internal navigation. Infinite loading uses cursor + revision snapshots, deduplication, abort on filter/unmount and an accessible Load more fallback. Live refresh rebuilds the loaded window against a fresh snapshot while retaining keyed rows; transient errors and cursor conflicts keep visible data, while changed filters never show old-filter rows. Separate ticket-owner filter supports username, Discord ID and mention; escalation badge and priority sorting.
- Initial-message previews replace legacy thread titles in the list, with ellipsis and immediate hover/focus scrolling at 100 px/s (minimum one-second duration), respecting reduced motion. Whole rows open details; the link remains keyboard accessible and text selection is preserved. Cached Discord names/avatars are serialized consistently for list/detail/actions without per-row Discord requests. Fallback: saved name, ID-matched legacy title, then ID; missing avatar uses official Avatar initials. Staff buttons share the detail header with Open in Discord; official Dialog opens fullscreen for optional reason and confirm/cancel, retaining text on failures and restoring focus.
- Web access requires `SUPPORT_TEAM_ROLE_ID` (production `784529945049038899`), falling back to `config.roles.support_team` only when unset. OWNER_ID has no access bypass. Each protected request verifies the role through the bot SDK, sharing only pending concurrent member lookups; completed results are not cached. Web actions also recheck the bot-side guild member. SSE checks every 15 seconds and carries only invalidations/sync status. Cookies, CSRF, HTTPS/CSP and scope checks remain enforced. Sign-in uses the identify OAuth scope only; no OAuth member endpoint is queried for each request.
- Staff actions: close, close and lock in one Discord edit, reopen, escalate to OWNER_ID, resolve escalation. Per-ticket action guard prevents overlaps. Escalation adds the owner to the private thread and mentions only that owner; repeated escalation does not send repeated notifications. Actor/reason/state are stored encrypted. Discord commands/buttons share the service; older ticket creation panels posted by this bot receive the public policy link automatically once per policy version.
- `MESSAGE_CONTENT_APPROVED=false` keeps full conversation collection disabled. `WEB_CHAT_ENABLED=false` independently hides chat in the dashboard. Both must be true to view archived conversations; excluded tickets remain inaccessible. When unavailable or excluded, hide the Conversation section and keep only the existing new-tab Discord button in the detail header. Web replies are separately gated by WEB_REPLIES_ENABLED=false; all three flags must be true. They use a bot-owned parent webhook with trusted threadId, fresh authenticated staff display name/server avatar, disabled mentions, per-ticket write guard and numeric-only safe delivery diagnostics. No bot-message or parent-channel fallback exists. Attribution survives Gateway/backfill/edit races and participates in local data erasure. Public policy describes the actual reply flag and processing. Message refresh replaces the recent snapshot so deleted content is not kept by merging stale pages.
- AES-256-GCM records/messages, HMAC indices, key authentication, opt-out/deletion and suppression against reimport. Retention: ticket open + 30 days after closure, without extending the deadline for a later lock/deletion; reopening starts a new open period. Legacy plaintext retirement remains a separate explicit, verified operation.
- `GET /api/stats`: separate header-only Bearer token (`STATS_API_TOKEN`, 32–256 chars); empty disables with 404, wrong/missing token 401. No Discord session required; token cannot read tickets. Encrypted numeric UTC daily counters only, retained for 730 inclusive calendar days. Day/Monday-week/calendar-month queries, bounded inclusive date range, zero buckets, totals/current counts and sync completeness. Historical events before `collectedSince` are not fabricated; old tickets first discovered are distinct from newly opened tickets. No IDs or content in the statistics response.
- `/privacy` and `/api/privacy` are public; policy describes actual flags, actions, providers, retention, numeric aggregates and contact info@devs.beer. Unknown hosting/email/backup facts remain explicit, not invented.
- Cloudflare managed tunnel `lonedev-tickets-web` and DNS `tickets.devs.beer` point to `http://127.0.0.1:7777`; token handoff is private and ignored by Git. Temporary account authorization was removed. Node supervises the pinned official checksum-verified cloudflared connector.
- Login persists in an HttpOnly/Secure/SameSite=Lax cookie for 30 days of use and in encrypted session rows in the existing SQLite store, surviving app/database restarts with the same keys. OAuth is used only for initial identity verification; its tokens are not stored. Logout and data erasure revoke session rows with minimal tombstones to block stale saves. Preauth state is capped at ten minutes; session cleanup runs every minute. Temporary bot API failures deny data access with 503 but preserve sign-in; SSE closes without falsely reporting session expiration, and logout remains available during an outage.
- Reconciliation/import diagnostic details are bounded to 20 actual failures with source IDs, stage and numeric code/status. Shared logger now preserves these allowlisted details and counts, excluding raw messages, requests and secrets. Startup no longer says service ready when synchronization is incomplete.
